Museo Universitario Alejandro Rangel Hidalgo

An accessible and responsive web platform designed to explore the Museo Universitario Alejandro Rangel Hidalgo’s four exhibition halls, consult visitor information, and book visits online.

  • Role: Frontend Developer and Accessibility Evaluator

02. The Goal of the Project

The main goal of the project was to design and develop an accessible website for the Museo Universitario Alejandro Rangel Hidalgo, enabling people with and without disabilities to consult information about its galleries, check admission costs, and book a visit.

Additionally, the project sought to evaluate whether the accessibility measures implemented based on WCAG guidelines functioned effectively in real-world usage scenarios, particularly with people who rely on screen readers.

03. Target Audience

The web platform is designed for visitors planning to explore the Museo Universitario Alejandro Rangel Hidalgo and access information regarding its exhibition halls, operating hours, admission pricing, and visit reservations.

Within this audience, special emphasis was placed on visitors with visual impairments—specifically blind and low-vision users who navigate using keyboard controls, screen readers, and other assistive technologies.

04. Key Challenges and Constraints

The primary challenge was seamlessly embedding accessibility into both UI design and frontend architecture, particularly across complex interactive components:

  • The visit reservation form.
  • The interactive date selection picker.
  • Form checkboxes and radio buttons.
  • Exhibition gallery cards.
  • Modal overlay windows.

A critical realization during this process was that technical compliance with WCAG criteria or high scores in automated scanner audits do not guarantee a completely accessible user experience.

Evaluation Constraints: The usability study was limited to three participants with visual impairments, conducted primarily using Google Chrome with the NVDA screen reader on desktop. Additionally, one participant evaluated mobile interaction using TalkBack on an Android device.

05. Design Strategy

From initial development, the platform was designed around the four core principles of WCAG 2.2: Perceivable, Operable, Understandable, and Robust. Key implementation strategies included:

  • Semantic HTML structure and landmark regions (header, nav, main, and footer).
  • Logical heading hierarchy.
  • Descriptive alternative text for images.
  • Proper contrast ratios between text and background.
  • Accessible forms with explicit labels and instructions.
  • Buttons and links with understandable, descriptive names.
  • Full keyboard navigation, logical tab order, and visible focus indicators.
  • Correctly defined page language attribute.
  • ARIA attributes to communicate names, states, and dynamic updates.
  • Fluid responsive design for desktop and mobile devices.

06. Evaluation Conducted

The accessibility evaluation was structured across three complementary methodology stages:

  1. Manual Inspection: Comprehensive code review evaluating document structure, contrast ratios, keyboard tab navigation, and ARIA control behavior against WCAG 2.1 AA criteria.
  2. Automated Evaluation: Automated scans using Lighthouse and Silktide to identify underlying technical issues related to HTML structure, color contrast, missing alt attributes, and ARIA labels.
  3. User Testing: Qualitative usability testing sessions with 3 participants with visual impairments (2 blind individuals and 1 low-vision user). Sessions were conducted on laptops running Google Chrome with the NVDA screen reader, with one participant also evaluating mobile navigation using TalkBack on an Android device.

User Task Scenario

"You are planning to visit the museum with a friend next Sunday, May 3rd, as you are both interested in seeing the pre-Hispanic ceramics gallery. Before leaving home, you decide to check the website to plan your schedule and calculate the budget for the visit."

  1. Find the admission price to enter the pre-Hispanic ceramics gallery.
  2. Book the visit to the ceramics gallery for two people for May 3, 2026.

07. Test Results and User Feedback

All three participants successfully completed the assigned task scenario, achieving a 100% completion rate. However, several key accessibility barriers and friction points were identified during testing:

Date Selection Picker

One participant received no auditory confirmation from the screen reader after picking a date. The remaining two participants encountered flawed keyboard tab order: pressing 'Tab' skipped the month and year fields entirely, jumping directly to subsequent inputs.

Modal Overlay Windows

Two participants interpreted interactive cards that opened modal overlays as static images. Another participant successfully opened a modal window but was unable to dismiss or close it using keyboard controls.

Additional Interaction Barriers

  • Certain form controls failed to announce their active/checked states to the screen reader.
  • Form validation errors were not communicated auditorily to screen reader users.
  • Keyboard focus was not automatically redirected to input fields containing errors.
  • The email address field was occasionally bypassed during keyboard navigation.
  • The numeric input field for selecting visitor count proved cumbersome to operate.
  • The navigation link labeled "Recorridos" (Tours) did not clearly communicate that it led to admission pricing.

Positive User Feedback

On a positive note, participants highlighted the comfortable visual contrast ratios, the seamless Dark Mode adaptability, and the overall high baseline accessibility of the platform.

08. Final Design and Improvements

The final outcome was a responsive, accessible web platform enabling visitors to explore exhibition galleries, consult museum information, and book visits online.

Visit the live Museo Universitario Alejandro Rangel Hidalgo (MUARH) website

Prioritized Improvements

Based on findings from user testing, the following key remediations were prioritized:

  • Correct keyboard focus order in the date selector picker.
  • Confirm selected dates dynamically using ARIA live status messages.
  • Properly announce form validation errors to screen reader users.
  • Improve keyboard focus control inside modal overlay windows.
  • Enable closing modal overlay windows via keyboard controls (e.g., 'Esc' key).
  • Utilize clearer, more intuitive navigation labels (e.g. changing 'Recorridos' to 'Costos').
  • Simplify the input control for selecting the number of visitors.
  • Review and optimize touch gesture target sizes for TalkBack and VoiceOver.

09. Conclusion

This project provided invaluable hands-on experience applying web accessibility principles across both UX design and frontend programming for a real-world digital experience.

Core Learning: Manual code inspections and automated tools (such as Lighthouse and Silktide) are essential baselines, but they cannot replace direct testing with real users. Even though all participants achieved a 100% completion rate, observing their live interactions revealed critical barriers related to keyboard focus, status messages, validation alerts, and interactive components.

Ultimately, the evaluation confirmed that accessibility must be approached as a continuous process of inclusive design, technical implementation, empirical user testing, and ongoing iteration.
